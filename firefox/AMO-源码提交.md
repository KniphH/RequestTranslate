## 提交时选了「是：使用过二次处理工具」

AMO 问：**「是否在扩展开发中使用过下列任一工具？」**

那四条里我们命中的是**最后一条**：

> 任何对代码或文件**二次处理**，并生成扩展中的代码或文件的其他工具

命中原因：打包时用仓库自带的 `tools/minify-sources.mjs` + `tools/strip-comments.mjs`
**剥掉了注释**。这不是 minify（不压行、不改变量名、不改 AST），但确实是「二次处理」。

### 为什么没选「否」

技术上最接近「否」（零依赖、无 webpack/rollup、无模板引擎、`dependencies` 与
`devDependencies` 都是空的），但：

- 注释确实被处理过，**包内与仓库里的文件不是逐字节相同**；
- 仓库是**公开的**，审核员一比就发现；
- 隐瞒源码问题在 AMO 是重罪，**会直接驳回甚至封号**。

选「是」并说清楚，比选「否」被拆穿划算得多。

## 上传的源码包

```
dist/request-translate-1.3.0-SOURCE.zip
```

41 个条目，256,380 字节（250.4 KB），CRC 全通过。内容 = **带完整注释的源码**
+ 构建脚本 + `BUILD.md`（重建说明）。

**不收**：`docs/`（开发文档）、`firefox/`（火狐调试环境）、`dist/`、`.git/`、
`.github/`、`.workbuddy/` —— 它们与扩展无关，混进去只会让审核员多问。

## 关键证据：行号守恒

剥注释**只清空注释内容、不删行**，所以包内与仓库**行数完全一致**。实测：

```
  文件                      仓库行数     包内行数  结论
  content.js                3021     3021  ✓ 相同
  background.js              631      631  ✓ 相同
  options.js                3570     3570  ✓ 相同
  popup.js                   208      208  ✓ 相同
  offscreen.js                25       25  ✓ 相同
  frame-bridge.js             86       86  ✓ 相同
  lib/panel-core.js          241      241  ✓ 相同
  lib/store.js               768      768  ✓ 相同
  lib/engine.js              738      738  ✓ 相同

  行数一致: 9 个 / 不一致: 0 个
```

**这一点很重要**：审核员不需要执行任何构建，拿 GitHub 源码忽略注释逐行比对即可。

## 重建命令（写在 BUILD.md 里了）

```bash

```

环境：Python 3.9+（只用标准库）+ Node 18+。**无需 npm install**。

## 过审之后要做的

1. 开发者中心 →「我的附加组件」→ 该版本 → **下载签名的 `.xpi`**
   签名版会比上传的那个**大一点**（Mozilla 往里塞了签名块）。
2. 把签名版挂到 **GitHub Releases**
3. 更新 `README.md` 的火狐安装说明：从「临时载入」改成「从文件安装 / 拖入窗口」
4. 可选：开发者中心「管理 API 密钥」→ `web-ext sign` 命令行签名，以后发版免网页
