# RequestTranslate

划词翻译扩展，但**配置不是一堆输入框，而是一整段请求文本**。

你写什么，它就发什么。

## 演示

划词 → 面板流式出译文（右上角「…」是逐项诊断：耗时、分片、响应路径）：

<img src="docs/demo.gif" width="720" alt="划词翻译演示">

设置页：左边是配置列表，右边就是一整段可编辑的 curl：

![配置示例](docs/settings.jpg)

</div>

````
curl https://api.ant-ling.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
  "model": "Ling-3.0-flash",
  # 此处以“Ling-3.0-flash”调用为例，可按需调整为“Ling-2.6-1T”
  "messages": [
    {"role": "user", "content": "请写一首关于春天的诗"}
  ],
  "stream": true
}'
````

从 API 文档里整段复制过来，把要翻的内容换成 `{{text}}`，存下，就能用了。
不用管插件支不支持某个参数、下拉框里有没有这个选项——参数是你自己写的，原样发出去。

## 安装（Edge）

1. 打开 `edge://extensions/`
2. 左下角打开 **开发人员模式**
3. 点 **加载解压缩的扩展**
4. 选择本文件夹（含 `manifest.json` 的那一层）

Chrome 同理，地址换成 `chrome://extensions/`。

装好后在工具栏找到紫色的双箭头图标，右键 → 「扩展选项」进设置页。

> 权限列表里会看到一条 **「读取和更改您的代理设置」**（`proxy`）。它只服务于 Bing 通道的
> [临时直连](#临时直连)，而那个开关**默认是关的** —— 只要你不用 Bing 通道，或者用代理客户端
> 自己的分流规则给 `bing.com` 放行，这条权限从头到尾都不会被用到。
>
> 另外两条是「翻译截图」用的：`offscreen`（开一个临时文档去读剪切板）和 `clipboardRead`（读剪切板）。
> 不用这个功能也不会被触发，[详情见下](#翻译截图ocr)。

## 第一次用

**什么都不用填，装上就能翻。**

内置的第一条配置是 **Bing 翻译（免费 · 无需 Key）**，默认选中的就是它。去任意网页划一段文字，选区旁边会出现一个小圆点，点它出结果。

想用自己的模型（质量更好、能控提示词）再往下走：

1. 进设置页 → **变量** 标签 → 把 `apiKey` 的值填成你自己的 key
2. 回 **配置** 标签，挑一条内置示例（OpenAI / DeepSeek / Ling / Ollama / Anthropic）改改
3. 点 **发送** 测试一下，能出结果就通了

还有一条路是**翻译截图**：系统截完图，在网页上右键 →「翻译剪切板中的截图」。
默认接的是硅基流动的 **PaddleOCR-VL**（调用免费，填个硅基流动的 key 即可），
识别出的文字照走你当前的配置翻出来 —— 见下面 [翻译截图（OCR）](#翻译截图ocr)。

## 核心概念

一条配置有两种类型，看你选哪种：

| 类型 | 怎么工作 | 什么时候用 |
| --- | --- | --- |
| **自定义请求** | 你写一段请求文本，除占位符外原样发出去 | 任何能用一次 HTTP 表达的 API（绝大多数） |
| **内置适配器** | 由扩展里的代码完成整个流程，不用你写请求 | 没法用单条请求表达的免费服务（目前是 Bing） |

### 内置适配器：Bing 免费通道

Bing 网页版翻译是**两步**：先 GET `bing.com/translator`，从 630KB 的 HTML 里正则抠出 `IG` / `IID` / `key` / `token`；再拿这些参数 POST 到 `ttranslatev3`。第二步的入参是第一步动态拿到的，请求模板写不出来——所以这段走代码，不进模板。

实测数据：

- 第一次翻译要抓一次页面，约 **1.5 秒**；之后 token 缓存一小时，单次 **0.8～1.2 秒**
- token 失效时 Bing 会返回 `HTTP 200` + **空 body**（光看状态码判断不出来），插件会重抓一次自动重试
- **开着代理时永远返回空 body** —— 节点把这个接口掐了，换节点也一样。**推荐在代理客户端里加一条 `DOMAIN-SUFFIX,bing.com,DIRECT`**（见下面「临时直连」）；插件自己也能临时切直连，但那个开关默认关
- 语言取设置里的**目标语言**，认「简体中文 / 繁體中文 / 英语 / 日语…」这些名字，也认 `zh-Hans` / `ja` 这种代码，认不出的回退到简体中文
- 单次上限 1000 字符（国内 5000），脚本依赖的是 `cn.bing.com`

译文质量不如大模型，胜在零配置、不要钱。

## 结果面板

```
┌────────────────────────────────────────────┐
│ ● [配置 ▾]                    👁  ↻  ⧉  ✕ │ ← ● 是状态灯，👁 切换原文显示
├────────────────────────────────────────────┤
│ 原文（可隐藏，和设置页那个开关是同一个）      │
├────────────────────────────────────────────┤
│ 译文，流式吐出来                            │
├────────────────────────────────────────────┤
│ HTTP 200 · 1.4s · choices[0].delta.content … │ ← 「…」是详细诊断
└────────────────────────────────────────────┘
```

**顶栏那盏灯**四态：透明 = 还没发请求，**紫** = 请求在飞（含流式吐字），
**绿** = 拿到了译文，**红** = 失败。三个「亮」的状态都带辉光，鼠标停上去还会告诉你
它是什么意思。绿灯说的是「这次请求成功了」——结果里带警告（比如有变量没喂上、
返回体不是合法 JSON）照样是绿灯，警告在状态栏和 `…` 里单独标黄。

**小圆点贴哪儿**：贴在选区**末尾那个字**的右下角，不是整个选区外框的右下角。
跨行选中时，整段选框的右边界会跑到最长那一行的末尾——离你松手的地方可能很远。
倒着拖选（鼠标停在选区开头）时会反过来贴开头。

**不跟网页缩放走**：网页按 `Ctrl + +` 放大时，页面上所有 fixed 定位的东西都会跟着变大。
面板用 `chrome.tabs.getZoom` 问出标签页的真实缩放比，再按 `1/zoom` 缩回来，
所以 100% 和 150% 下面板的物理尺寸是一样的。按钮不用 `transform` 而是把尺寸写成
CSS 变量（`--rt-tr-size` 等）、按 `1/zoom` 缩，这样它的 hover 放大（×1.08）照常工作，
尺寸也不会被内联样式写死。

状态栏只放三段：**HTTP 状态 · 总耗时 · 命中路径**。想看更多就点右边的 `…`：

| 字段 | 意思 |
| --- | --- |
| **首字** | 第一个**译文**分片出现的时间。你实际等的就是它，不是总耗时 |
| 总耗时 | 从发出请求到流结束 |
| 响应格式 | 自动判定出来的：`SSE` / `JSON` / `NDJSON` / `TEXT` |
| 分片 | 一共收到多少个数据块 |
| 响应大小 | 收到多少字节 |
| 命中路径 | 译文是从响应里的哪个字段取出来的 |
| 模型思考 | 有值就说明模型在偷偷思考（`reasoning_effort` 没生效），标黄 |

**「模型思考」不为 0 时，`…` 按钮自己会变黄**——不用展开就知道有问题。实测同一句话：

| | 首字 | 思考字数 | 响应大小 |
| --- | --- | --- | --- |
| `reasoning_effort: "none"` | 0.79s | 0 | 2.3 KB |
| 不带这个参数 | 5.00s | 1454 | 46 KB |

慢 6 倍、体积大 20 倍，全在那 1454 个字上。

## 核心概念

就三个东西。

### 1. 请求模板

一整段文本，两种写法任选。

**一条配置可以带两段模板**：普通那段翻文字，另有一段可选的 **图片请求模板**，
只在「右键 → 翻译剪切板中的截图」并且勾了「禁用外置 OCR」时用。
两段互不干扰 —— 图片那次可以直接写成多模态的样子：

```json
{"role":"user","content":[
  {"type":"image_url","image_url":{"url":"{{image}}"}},
  {"type":"text","text":"把图里的文字翻成{{target}}，只输出译文"}
]}
```

图片模板**留空就回退到普通那段**，所以老配置和「只想写一段」的情况都不受影响。
详见 [翻译截图（OCR）](#翻译截图ocr)。

**curl 写法** —— 直接从文档复制。支持：

| 写法 | 说明 |
| --- | --- |
| `-H "K: V"` / `--header` | 请求头 |
| `-d '…'` / `--data-raw` / `--data-binary` | 请求体，多个会拼起来 |
| `-X POST` / `--request` | 方法。不写的话：有 body 当 POST，没有当 GET |
| `-u user:pass` | 自动生成 `Authorization: Basic …` |
| `-G` | 把 `-d` 的数据并到 URL 的 query 上 |
| `-A` / `-b` / `-e` | User-Agent / Cookie / Referer |
| `\` 换行 | 续行 |
| 行首 `#` | 注释，会被忽略 |

**原始 HTTP 报文写法** —— 不想写 curl 就直接写：

````
POST https://api.anthropic.com/v1/messages
x-api-key: {{apiKey}}
anthropic-version: 2023-06-01
content-type: application/json

{
  "model": "claude-3-5-haiku-latest",
  "max_tokens": 2048,
  "messages": [{"role": "user", "content": "{{text}}"}],
  "stream": true
}
````

第一行是「方法 + URL」，接着是 header，空行之后全是 body。

### 2. 占位符

模板里的 `{{...}}` 会被替换掉，只有这些位置会动，其余一个字节不改。

| 占位符 | 值 |
| --- | --- |
| `{{text}}` | 选中的文字（也可以用 `{{selection}}`）。截图直传时是空串 |
| `{{image}}` | 截图翻译时那张图的 data URL；普通划词翻译时是空串。见下面「翻译截图（OCR）」 |
| `{{imagePart}}` | 上面那张图对应的**一整段 content 元素**（含前导逗号）；没图时是空串。见下面「一段模板两用」 |
| `{{target}}` | 设置里的目标语言，默认「简体中文」 |
| `{{targetLang}}` | 同上 |
| `{{url}}` / `{{title}}` | 所在页面的地址 / 标题 |
| `{{date}}` | 今天的日期 |
| `{{任意名字}}` | 你在 **变量** 标签里定义的值，比如 `{{apiKey}}` |

**插进去的时候会自动转义**。判断依据不是「紧挨着的是什么字符」，而是**这个占位符此刻落在哪几层引号里**，从内到外逐层转义：

| 模板里写成 | 落在一层 | 效果 |
| --- | --- | --- |
| `"{{text}}"` 或 `{"content":"…{{text}}…"}` | JSON 字符串 | JSON 转义（`"` → `\"`，换行 → `\n`） |
| `'{{text}}'` | shell 单引号 | shell 转义（`'` → `'\''`） |
| `-d '{"content":"…{{text}}…"}'` | **两层** | 先 JSON 转义，再 shell 转义 |
| `{{text}}` | 不在引号里 | 原样插入 |

所以选中一段带引号、带换行的文字，也不会把 JSON 撑破。

**最后「两层」那条是 curl 模板的常态，也是最容易踩的**：外面是 shell 的单引号（`-d '…'`），里面才是 JSON 字符串。这时 `{{text}}` 两侧既不是 `"` 也不是 `'`（多半是 `\n` 之类），只看两侧会当成原样插入 —— 于是文本里一个撇号就能把外层单引号提前闭合，请求体从那儿被截断，接口只回你一句
`JSON parse error: Unexpected end-of-input in VALUE_STRING`。翻英文时几乎必然踩到（`Pixeldrain's`、`There's`…），中文日文则一直碰不上。现在这种情况会两层都转义。

> 副作用：设置页的「渲染预览」里，落在两层引号中的占位符会显示出 `'\''` 这种 shell 拼接写法 —— 那正是它要被 shell 解析的原样，不是坏掉了。

### 3. 响应提取路径

请求发出去之后，总得知道从返回的 JSON 里哪儿取译文。

留空就行——会依次尝试各家常见结构：

```
choices[0].message.content      OpenAI / DeepSeek / 大部分中转
choices[0].delta.content        OpenAI 流式
delta.text                      Anthropic 流式
content[0].text                 Anthropic 非流式
candidates[0].content.parts[0].text   Gemini
message.content                 Ollama
data.translations[0].translatedText   Google 翻译
```

要是某个服务结构比较特别，手动填路径。语法是 `点号 + 下标`：

```
data.translations[0].translatedText
output.choices[0].text
["奇怪的 key"].value
```

设置页右下角的 **发送** 按钮会把 HTTP 状态、耗时、命中的路径、提取结果、原始响应全列出来，对不上了一眼就能看出来。

## 配置列表

左栏那几条配置可以改顺序：**按住左边的手柄上下拖**，或者**点右边的 ↑ ↓**（键盘也行）。

顺序是有意义的 —— 右键菜单、工具栏弹窗里的配置下拉、划词面板顶栏的配置下拉，**都按这个顺序排**。常用的挪到最上面。

- 手柄平时很淡，鼠标进那一行才亮起来。整行做成可拖会跟「点一下选中」抢鼠标，所以拖拽源只有那一个手柄
- 拖动时目标位置画一条紫线；只是点一下手柄（晃 2px 以内）不会误排序
- 首尾两行的 ↑ / ↓ 是禁用的 —— 点了也不会有反应，索性禁掉
- 改顺序**不会**动「当前选中」，也不会改任何一条配置的内容
- 顺序存在配置里（`state.configs` 就是个数组），导出 JSON 会连着顺序一起带走

### 翻译截图（OCR）

用系统截图（Win + Shift + S 之类）截一张图，图片就进了剪切板。在任意网页上
**右键 →「翻译剪切板中的截图」**，扩展会把它认成文字，再按「配置」里当前那条翻译出来。

剪切板里第一项不是图片时会直接告诉你「剪切板里没有图片」——不会拿一段文字硬翻，
也不会瞎发请求。这条菜单和「翻译选中内容」**各有一个开关**，想只留一个很正常。

**供应商在设置页单独一栏（「OCR」标签）里管。** 它和「配置」一样是一张列表，
可以填接口地址、模型、API Key，能新建 / 复制 / 删除。默认给了两条：

| 内置 | 接口 | 模型 | 费用 |
| --- | --- | --- | --- |
| 硅基流动 | `api.siliconflow.cn/v1/chat/completions` | `PaddlePaddle/PaddleOCR-VL-1.5` | 免费 |
| OpenAI 兼容（VL） | `api.openai.com/v1/chat/completions` | `gpt-4o-mini` | 要钱 |

要的是一套 **OpenAI 兼容的 `chat/completions`**：截图以 data URL 塞进
`messages[0].content` 的 `image_url`，文字从 `choices[0].message.content` 取。
提示词里给了几个可以点的短指令（`OCR:` / `Table Recognition:` / `Formula Recognition:` /
`Seal Recognition:`），PaddleOCR-VL 认这几个前缀。

**「最大输出长度」（`max_tokens`）建议留空。** 留空就是不发送这个字段，由服务端按模型
自己的上限定。这是踩过坑才这么定的：这个上限是「提示词 + `max_tokens`」**加在一起**算的，
而各家的上下文宽度差得很远 —— 写死 8192 会在上下文窄的模型上直接 400，比如
`deepseek-ai/DeepSeek-OCR` 的 `max_seq_len` 只有 8192：

```json
{"code":20015,"message":"max_tokens (8192) have exceeded max_seq_len (8192) limit.","data":null}
```

（这种报错现在会附带一句「把「最大输出长度」清空」，不用你自己查。确实要限长再填，
填的数得给提示词留出余量。）

**外面（右键菜单）不给你挑供应商** —— 用哪条只看设置页里选中的那一条，想换先切过来。
理由很简单：右键菜单是个单层列表，塞不下「先选供应商再选模型」那一套。

#### 配好了先在设置页测一下

「OCR」那一栏底下和「配置」栏一样有个**测试**：不选文件就直接读**剪切板里的第一张图**
（就是你刚截的那张），也可以先挑一张本地图片。点一下会真发一次请求，把
**HTTP 状态 / 耗时 / 图片大小 / 识别到的文字 / 实际请求 / 原始响应**全摊在页面上。

跟外面右键走的是同一套配置（接口 / 模型 / 最大输出长度 / Key / 提示词），
**这里能出字，右键就一定也能**。
出错时同样把响应体带出来，401、404、模型名写错一眼就看得出来。
请求头那栏里的 key 是打了码的，设置页截图分享出去也不会顺手把 key 送人。

勾了「禁用外置 OCR」时这个按钮会变灰 —— 那种模式下这条供应商根本不会被动用。

#### 禁用外置 OCR：把图片直接交给模型

如果你当前那条配置对应的模型**自己就能看图**（多模态），可以勾上「禁用外置 OCR」——
这一步不做识别了，截图被**原样塞进当前那条翻译请求**，由模型自己看图 + 翻译，省一次来回。

这时给这条配置写**第二段模板**（「配置」栏里那个 **图片请求模板**）就行，普通那段继续翻文字：

```json
{"role":"user","content":[
  {"type":"image_url","image_url":{"url":"{{image}}"}},
  {"type":"text","text":"把图里的文字翻成{{target}}，只输出译文"}
]}
```

两段模板各管各的：

| 你怎么操作 | 用哪段模板 | `{{text}}` | `{{image}}` |
| --- | --- | --- | --- |
| 划词 / 右键「翻译选中内容」 | 普通那段 | 选中的文字 | 空串 |
| 右键「翻译剪切板中的截图」+ 勾了禁用外置 OCR | **图片那段** | 空串（图片就是原文） | 那张图的 data URL |
| 右键「翻译剪切板中的截图」，没勾 | 普通那段 | OCR 认出来的文字 | 空串 |

**图片模板留空就回退到普通那段**，所以只写一段、或者老配置（压根没这个字段）都不会出问题。
设置页的「渲染预览」会把两段都渲一遍，省得靠猜。

直传那一次，结果面板的原文区会写明「这张截图直接发给了模型，没有先做外置 OCR」，
状态栏也会标成「截图直传」而不是「截图 OCR」——省得你以为哪一步没跑。

#### 只想写一段？用 `{{imagePart}}`

不想维护两段模板的话，`content` 写成数组、末尾挂一个裸的 `{{imagePart}}` 也能一段两用：

```json
{"role":"user","content":[{"type":"text","text":"仅输出{{target}}译文：\n\"\"\"\n{{text}}\n\"\"\""}{{imagePart}}]}
```

没图时 `{{imagePart}}` 是空串 → `content` 里只有一个 text 段（和原来等价）；
有图时它变成 `,{"type":"image_url","image_url":{"url":"data:…"}}` → 自动多出图片段。

两个注意点：它**必须裸着写**（套上引号会被当字符串转义，整段 JSON 就坏了），
而且**只能放数组最后一项** —— JSON 数组第一项前面不能有逗号，占位符没法知道自己是第几个。
想把图片放最前，就用上面那两段模板的写法。

#### 几个实现上的点

- **剪切板只能在 offscreen 文档里读。** content script 读不到（拿不到焦点、没有权限），
  所以扩展临时开一个 `offscreen.html`，读完就把这个文档关掉（省内存），不是常驻。
- **不猜 `blob.type`。** Windows 截图工具丢出来的那一项，类型可能是**空串**——
  直接用 `blob.type` 会拼出 `data:;base64,…`，接口那边直接拒。所以按**文件头**认（PNG/JPEG/GIF/BMP/WEBP 魔数）。
- **大图的 base64 要分块转。** 几十万字节一次性 `String.fromCharCode.apply` 会把调用栈撑爆。
- **「机制坏了」和「里面没图」分开报。** 读不到剪切板（浏览器没放开权限）说的是
  「读不到剪切板，浏览器没放开剪贴板权限？」，不会冒充「剪切板里没有图片」。

### 翻译按钮

划词后出现在选区旁边的那个小按钮，在设置页「翻译按钮」一栏里换样子：

| 预设 | 长什么样 |
| --- | --- |
| **译字方块** | 紫色渐变圆角方块 + 一个「译」字（默认） |
| **地球** | 正圆底 + 线描地球（带经纬线） |
| **笔尖** | 正圆底 + 钢笔笔尖 |

大小单独调（20–96px）。地球和笔尖是线性图标，颜色跟着**主题**走（暗色下浅紫、亮色下深紫）。

三个都不喜欢，就在下面的 **自定义图标（SVG）** 里粘一段自己画的 `<svg>…</svg>`。
它会顶掉预设里的图标 /「译」字，**底座（底色、圆角、大小）还是用上面选的那个预设**：

```html
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.8">
  <path d="M4 12h10M9 7l5 5-5 5"/>
</svg>
```

颜色写 `currentColor` 就跟着主题走（暗色浅紫 / 亮色深紫），写死颜色也行。
设置页右边有**实时预览** —— 它用的是和真实按钮**完全同一份**样式表（都在各自的 shadow root 里），
所见即所得；左边那排卡片上画的也就是各预设的样子。下面还有个「插入示例图标」可以直接拿去改。

这段代码最终是 `innerHTML` 插进页面的 shadow DOM 的，所以做的是**白名单式整段校验**：
不通过就整段不用（并告诉你卡在哪一条），而不是悄悄帮你去掉危险的部分。

| 要求 | 为什么 |
| --- | --- |
| 以 `<svg` 开头、以 `</svg>` 结尾 | 免得把整段 HTML 塞进来 |
| 不含 `<script>` / `<foreignObject>` / `<iframe>` / `<image>` / `<use>` / `<a>` / `<style>` / `<animate>` / `<set>` | 这些能执行代码或拉外部资源 |
| 不含 `onload=` / `onclick=` 这类事件属性 | 同上 |
| 不含 `href=` / `xlink:href=` | 外链 |

**为什么是「整段拒绝」而不是「剔除危险标签」**：content script 能碰到 `chrome.*`，
放进来一段能执行的东西代价太大；而「剔除」太容易漏 —— 大小写、`xlink:` 命名空间、
`<use>` 引用外部符号…… 漏一个就等于没防。判据在 `lib/trigger-styles.js` 的 `SVG_GUARDS`。

两件实现上的事，知道一下省得踩坑：

- **预设样式都写成 `.rt-trigger:where(.s-badge)` 这种形状。** `:where()` 不贡献优先级，
  所以预设整条算下来只有 `(0,1,0)`。以后想在预设之上再叠一层样式，直接写
  `.rt-trigger { … }` 就压得住，不需要 `!important`。
- **按钮尺寸是 CSS 变量（`--rt-tr-size` 等），不是内联样式。** 内联会挡住外面来的样式，
  形状就锁死了。变量还有 `--rt-tr-radius` / `--rt-tr-font`，
  圆形预设的底色 / 图标色 / 描边色是 `--rt-tr-bg` / `--rt-tr-fg` / `--rt-tr-bd`。

### 面板的位置

面板默认贴选区右下角，右边放不下就翻到左侧。**四个方向都夹在视口里**：拖也拖不出去
（以前往右下拖能拖到只剩一条边露在外面），正文一段段变长时（流式输出、展开原文或诊断）
也会自动把自己拉回来。

坐标这块有个容易搞错的地方：面板是 `fixed` + `transform: scale(1/zoom)`，而
`transform-origin` 是左上角 —— 缩放**不会移动左上角**，但宽高要乘 `1/zoom`。
所以夹取得拿「布局尺寸 × 1/zoom」去算；直接拿 `offsetWidth` 和 `innerWidth` 比，
网页一缩放就会从右边或下边溜出去。

### 临时直连

Chromium 里没有「这一次 fetch 别走代理」的开关 —— 扩展发的请求一律跟着系统代理走。
而开着代理时 Bing 的翻译接口会稳定回一个**空 body**（节点把它掐了），所以这条免费通道基本废掉。

**首选做法是在代理客户端里解决**，插件这边什么都不用开：

```
DOMAIN-SUFFIX,bing.com,DIRECT
```

（mihomo / Clash 系写进 `rules:`，其它客户端等价写法即可。）流量在出网卡之前就分好流了，
浏览器代理设置根本不用碰，扩展也不需要那条「读取和更改您的代理设置」权限 ——
**所以下面这个开关默认是关的。**

改不了代理客户端（公司策略、别人给的配置），或者就是不想加规则，再到设置页「网络」里
打开 **「用内置适配器（Bing）时临时直连」**。它用的办法是**临时改浏览器代理**：
发请求前把代理切成直连，拿到响应头（连接已经建好）立刻切回来。
窗口通常只有几百毫秒，而且只包住 `fetch` 本身，不包住后面的流式解析。

几个实现上的取舍：

- **能窄就窄。** 读得到原代理地址时（别的扩展设的 `fixed_servers`）生成一段 PAC：
  只有本次请求的域名走直连，其余流量照旧走原代理。地址读不到时（系统代理 / 自动检测 / PAC）
  只能整机切直连 —— 这段时间里浏览器其他**新建**连接也会直连，已经建好的连接不受影响。
- **收尾用 `clear()` 而不是写回旧值。** 写回旧值会让本扩展一直「压着」代理设置
  （`levelOfControl` 变成 `controlled_by_this_extension`），之后你在代理软件里改端口就不生效了。
  `clear()` 是交还控制权，会自然回落到系统设置 / 别的扩展 / 策略。
- **service worker 被回收时可能留下直连状态**，所以每次 worker 启动都会跑一次自检，
  发现「代理正被本扩展控制着」就交还回去。
- 自定义配置里也有自己的「强制直连」开关，适合「开着代理时某个接口反而连不上」的情况。

> **TUN / 虚拟网卡模式下这个开关没用。** 流量在网卡层就被抓走了，改浏览器代理设置影响不到它 ——
> 只能回到上面那条规则（`DOMAIN-SUFFIX,bing.com,DIRECT`）去解决。

## 性能

`npm run perf` 会用系统 Edge 真加载扩展，量主线程的实际任务时间。实测：

| 场景 | 主线程占空比 |
|---|---|
| 空闲（页面静止，无选区无面板） | **0.0%**（5 秒内共 2ms） |
| 连续滚动 3 秒 | 0.9% |
| 连续划词 40 次 | 3.0%（每次约 0.7ms） |
| 流式翻译：800 字 / 100 分片 | 3.4% |
| 流式翻译：8000 字 / 500 分片 | 4.0% |

几点结论：

**空闲零消耗。** 没有 `setInterval`、没有 `MutationObserver`、没有常驻动画，只在划词和点按钮的时刻干活。

**滚动和划词的开销可以忽略。** 滚动处理只是给一个元素去掉 class；划词每次约 0.7ms。

**唯一真正花钱的是流式渲染**，成本正比于「渲染次数 × 译文长度」——每渲染一次，浏览器就要把整块译文重新排版一遍。所以流式输出做了 50ms 时间节流（约 20fps）：

| 负载 | 节流前 | 节流后 |
|---|---|---|
| 800 字 / 100 分片 | 52ms | **37ms** |
| 1000 字 / 500 分片 | 115ms | **45ms** |
| 8000 字 / 500 分片 | 435ms | **142ms** |

试过但**实测无效**的做法：把两次强制布局减为一次、用 `requestAnimationFrame` 合并、原地改写文本节点——都在噪声内（±3%）。因为分片间隔本来就接近刷新率，合并不了多少。唯一有效的杠杆是「少渲染几次」。

**节流对慢速接口完全无副作用。** 分片间隔超过 50ms 时，每个分片都立即渲染，和没节流一模一样。只有分片涌进来的场景（本地模型、开着思考的模型）才会触发节流，而那正是需要省的地方。请求结束时 `done` 会立刻写入最终文本，尾巴上不会少字。

想更激进可以改 `content.js` 里的 `RENDER_INTERVAL`（毫秒）：调大更省，但流式观感会变钝；设为 `0` 等于关掉节流。默认 50 是实测的折中。

## 几个坑，提前说

**JSON 里不能有裸换行。** 这是 JSON 的规矩不是插件的。所以提示词要写成：

```
"content": "仅输出{{target}}译文：\n\"\"\"\n{{text}}\n\"\"\"\n输出示例：\nThe translated text itself"
```

模型实际收到的会是：

```
仅输出简体中文译文：
"""
原文内容
"""
输出示例：
The translated text itself
```

内置配置就是这么写的，照着改就行。忘了转义也不至于崩——插件会尝试自动修复（剥掉注释行、把裸换行转义成 `\n`）并在结果里提示你。

**混合推理模型会先「思考」再作答，翻译场景要把这个关掉。** Ling-3.1、DeepSeek-R 这类模型默认先吐一大段推理再给答案，你看到的就是「半天不出字」。实测 Ling-3.1-flash 翻一句话：

| 写法 | 首个思考分片 | 首个**译文**分片 | 输出思考字数 |
| --- | --- | --- | --- |
| 不带任何参数（默认） | 0.5s | **7.2s** | 2354 |
| `"reasoning": {"effort": "none"}` | 0.7s | **7.3s** ← 没生效 | 2185 |
| `"reasoning_effort": "none"` | —— 从不出现 | **0.5s** | 0 |

关掉思考用的是**顶层** `reasoning_effort`：

```
"reasoning_effort": "none"
```

**别写成 `"reasoning": {"effort": "none"}`。** 那个嵌套写法是 Vercel AI Gateway 这类中转自己桥接出来的，`api.ant-ling.com` 直连不认——而且**不报错，静默忽略**，你会以为关了、其实思考照跑。参数名对不上时，接口不会提醒你，只能实测。

**不用自己实测了**：结果面板右下角 `…` 里的「模型思考」就是干这个的。它是 0 说明关干净了，有数字就是没生效（`…` 按钮还会变黄）。

要留一点思考的话，`"reasoning_effort"` 也接受 `"low"` / `"medium"` / `"high"`（`none` 之外都会产生独立的 `reasoning_content` 流，插件只取 `content`，思考内容不会混进译文）。

**有些 header 改不了。** 浏览器规定 `Host`、`Content-Length`、`Origin`、`Cookie`、`User-Agent` 这些由浏览器自己管，写在模板里会被忽略。需要鉴权的用 `Authorization` / `x-api-key` 这类正常的头。

**跨域不用担心。** 请求实际发生在扩展后台（`background.js`），有 `host_permissions: <all_urls>`，不受页面 CORS 限制。

**API Key 存在本地。** `chrome.storage.local` 里明文存着，没加密。这是你自己的机器和使用习惯问题——别把导出的配置文件分享出去。

## 开发

```bash
npm test              # 静态检查 + 单元 + 端到端 + 真实浏览器 UI（598 项）
npm run check         # 只跑两项静态检查
npm run test:lib      # 解析器 / 模板 / 提取
npm run test:engine   # 本地 mock 服务器，验证各类响应格式
npm run test:ui       # 开真实 Edge 加载扩展，量 DOM 实际尺寸
npm run perf          # 量性能：主线程任务时间 + 进程 CPU，四档流式负载对照
npm run icons         # 重新生成图标
```

`npm run perf` 只跑指定档位可以快很多：`PERF_ONLY=heavy npm run perf`（可选档位 `normal` / `fewLong` / `manyShort` / `heavy`）。

拆开看是 `test-lib` 355 项、`test-engine` 79 项、`e2e-ui` 162 项，另加两项静态检查。这几层各自补不同的盲区：

- **`check-globals`** — 语法检查看不出 `bindConfigList()` 这种「调用了但没写」，只有运行时才炸。它把注释、字符串、正则字面量剥掉之后逐个比对调用与声明。也可以指定文件：`node tools/check-globals.mjs lib/engine.js`
- **`check-dom`** — 比对 JS 里的 `$('#id')` / `querySelector('.x')` / `closest('.x')`，和「HTML 里写死的**加上** JS 里拼出来的」类名，防的是「选择器指向不存在的元素，启动时炸在 null 上」。动态建节点用的类名（`row.className = 'cfg-row'`）在 HTML 里找不到，所以脚本里拼过的名字也算数。
- **`e2e-ui`** — 前两项都只能说「代码能跑、选择器对得上」，管不了**长得对不对**。这个脚本用系统 Edge（`playwright-core`，不下载浏览器）加载扩展，真去划词、点按钮，然后用 `getBoundingClientRect` 量出顶栏多高、面板多宽、缩放后尺寸有没有变。状态灯那三态（紫/绿/红）也在这里钉住：靠假接口里那个 `/slow`（挂 1.2 秒）把「请求在飞」的瞬间停住才采得到紫灯。没装 Edge 会自动跳过。截图 OCR 那一段会**往系统剪切板里真塞一张 PNG**（PowerShell）再跑全链路，而且必须开**有头**窗口 —— 无头 Chromium 的剪切板是桩实现，读回来永远是空的。

改完代码在扩展管理页点一下「重新加载」，**然后刷新目标网页** —— 两件都要做。

只重新加载扩展不够：已经在开着的页面里跑的是**旧的那份 content script**，它不会自己换成新的
（而且扩展一重新加载，旧脚本手里的 `chrome.*` 就失效了）。症状很好认：设置页明明是新的、
预览也对，网页上却还是老样子。

## 限制

- 只在顶层文档划词，iframe 里的选区拿不到
- 面板是覆盖层，页面全屏播放视频时会看不见
- 不支持 `-F` 上传文件、`-d @file` 这类需要文件系统的 curl 参数
- 没有快捷键，只有划词小圆点 / 右键菜单 / 弹窗三种入口
- **翻译截图只认剪切板里的第一项图片**，而且只在这台机器上浏览器能读剪切板时才行 ——
  系统级剪贴板管理器有时会把图片转成别的形态，那就读不到了
- **截图翻译的供应商只能在设置页选**，右键菜单里不给临时切
