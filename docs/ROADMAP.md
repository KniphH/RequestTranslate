## 2026-10-18 复查（轻量）：maxChars 是 historyMax 那个漏洞的漏网

第 1 轮修了 `importState` 不归一化 `historyMax`；复查发现 **`maxChars` 有一模一样的洞**，
而且触发路径更日常：

- 设置页那个输入框的 `save` 是 `Number(el.value) || 0` —— **用户清空输入框就写进 0**；
  导入的文件里还可能是 `"abc"` / `-5` / `null`。
- 三个消费方表现不一致：`content.js` 和 `background.js` 都有 `Math.max(1, Number(x) || 8000)` 兜底，
  **只有 `popup.js` 直接 `slice(0, x)`** —— `slice(0, 'abc')` 和 `slice(0, 0)` 都得到空串，
  于是**弹窗里选中的文字整个消失**；`slice(0, -5)` 还会从尾部倒砍。

已修三处：`store.js` 加 `normalizeMaxChars`（loadState + importState 都调）、
`popup.js` 补上和另两处一样的守卫、设置页清空时退回 8000 而不是写 0。
断言从 946 → **955**（+9，其中 7 条钉归一化的边界、2 条钉源码守卫在场）。

> **教训**：修「某个字段没归一化」时，要**把所有同类型的字段一起过一遍**（`DEFAULT_SETTINGS` 里
> 每一个 number 型都该问一句「坏值会不会穿到消费方」），而不是只修报出来的那一个。
