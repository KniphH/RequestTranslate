## 一、设计原则（不可动摇）

1. **零依赖、零构建**：解压即可加载，没有 `npm install` 才能跑的步骤。
2. **一条配置 = 一整段可编辑的请求文本**（curl 或原始 HTTP 报文），除占位符外一个字节都不改写。
   表达不了的（Bing 两步流程）放 `lib/adapters.js`，返回结构与 `engine.runRequest` 完全一致。
3. **只内置一种语言**（中文，源码即文案）；其余语言包从仓库下载，**不进包**。
   体积优先：能下载的都不进安装包。
4. **一处真相源**：语言映射、messages 剥离规则、测试计数、面板与设置页共用的块渲染，
   都只留一份实现；内容脚本不能 `import` 的（CSS / SVG），配逐字比对断言。

## 二、关键决策

| 时间 | 决策 | 原因 |
|---|---|---|
| 2026-10-14 | 包里剥注释、仓库留完整源码 | 看源码的人才需要注释；装扩展的人不会打开 `content.js` |
| 2026-10-14 | 再上 esbuild 压 JS，但**跳过 `lib/panel-core.js`** | 它内嵌约 20 KB CSS，压了反而膨胀 67% |
| 2026-10-18 | 语言包改为「从仓库下载」，不打包 | 体积原则；代价是必须处理好缓存与版本错位 |
| 2026-11-09 | 导出支持口令加密（AES-GCM） | 明文 Key 的备份文件不适合外发 |
| 2026-11-15 | 语言包维持「完全下载」，不做内置 | 明确要求：不为了离线可用破坏体积原则 |

## 三、踩过的坑（最值钱的部分）

| 症状 | 根因 | 现在怎么防 |
|---|---|---|
| 报错栈行号对不上源码 | esbuild 把文件压成几行 | 按函数名 / 字符串定位；`verify-pack` 只对未压缩文件验行号 |
| 英文界面里夹着中文 | 语言包从仓库下载，本地缓存是旧的，新 key 缺失就回退中文 | 语言包随仓库更新；**换语言 = 重新下载**；缺 key 时优先怀疑缓存 |
| 设置页显示 `[object Object]` | 引擎把 warning 改成 `{code,text}`，设置页仍当字符串拼 | 统一 `warnText()`，4 个渲染点都走它，有断言 |
| 打包跑到一半中断 | 系统的批量删除保护让 `shutil.rmtree` 抛 `BaseException`，`finally` 里抛错会跳过后续输出 | 所有清理都 `try/except BaseException`；临时目录固定为 `dist/.verify`，不再累积 |
| 同源检查「抓不到旧包」 | 同上：清理抛错 → 跳过 problems 打印 → 夹具只看到「非零退出、没有报错」 | 清理永不抛错；夹具断言「报错必须来自同源文案」 |
| e2e 偶发假红（变量顺序） | 断言固定等 600 ms 读存档，机器忙时不够 | 改成轮询等落盘（最多 3 秒），顺序仍严格比较 |
| 加 `$1$` 的 key 报错 | Chrome i18n 要求 `placeholders` 声明 | `test-lib` 有「每个 `$N$` 都声明了等量 placeholders」断言 |
| 改文案后英文不变 | 文案拼在 `engine` / `adapters` / `parser` 里，不走 i18n | 引擎在错误上带 `code`，边界层（background / 设置页）翻译一次 |
| 火狐里 bilibili 必被风控 | 依赖了只有 Chromium 有的扩展 API | UA / Origin 写进配置模板，不依赖 API |
| 火狐后台被回收后卡死 | 事件页 30 秒回收，端口断开 | 自动重连 + 批次判废；不谎称完成 |
| 右键菜单全空 | i18n 改造漏改 3 处调用 | 「改名要扫全文件」断言，扫描不再以「import 是否改名」为前提 |

## 五、火狐移植结论

同一份代码、同一套 `pack.py`，靠 `--target firefox` 裁 manifest（只留 `background.scripts`）。
火狐包比 Chromium 包少 3 个专有文件；其余 29 个共同文件逐字节一致。
不需要 polyfill、不需要构建步骤。
