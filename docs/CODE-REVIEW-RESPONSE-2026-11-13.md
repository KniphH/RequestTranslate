## 三、两个自查抓到的真 bug

### 1. 断言自身查错了对象（已修）

新加的「代码 key ⊂ en 包」断言启用时立刻自己报红：

```js
const enKeys2 = Object.keys(...)   // 数组
k in enKeys2                       // 查的是下标，不是 key！
```

中文包那侧用的是 `in zhAll`（对象，对），英文那侧用了数组（错），
所以它一直显示「通过」。改成 `Set` 后正常。

**这条本身就是「验证器要有夹具」的例证。**

### 2. 同名参数遮蔽 import（P0，e2e 抓到）

给 background.js 的 OCR 状态行接 i18n 时写了：

```js
import { msg } from './lib/i18n-msg.js';
port.onMessage.addListener(async (msg) => {
  safePost({ type: 'ocr-status', message: await msg('bg_reading_clipboard', ...) });
```

**参数 `msg` 遮蔽了 import 的 `msg` 函数** —— 调用它实际是在调用消息对象本身，
抛 TypeError，整个 OCR 处理器当场崩掉。

症状：面板永远停在「正在读取剪切板…」，**e2e 当场 25 条红**。

#### 为什么 check-globals 没抓到

它检查的是「有没有未定义的函数调用」—— 而 `msg` **确实有定义**，只是被参数盖住了。
静态名字检查看不出遮蔽。

修：`import { msg as tMsg }`，5 处调用点改名。

补了一条断言：如果文件里有 `async (msg` 这类回调参数，且 import 的名字就是 `msg`（没 as 改名），就报红。
