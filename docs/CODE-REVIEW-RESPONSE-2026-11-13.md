## 一、本轮清完的

### 1. content.js 的 12 处硬编码中文状态行

第十版说「状态行几十处硬编码」，实际扫出 12 处 `setStatus`：

```
后台被系统回收 / 已切到「X」/ 请求中… / 翻译中…（N 条）/ 处理中…
没识别出文字 / 扩展已更新 / 已复制 / 复制失败 / 已收起「X」
这个浏览器不支持朗读 / 目标语言：X
```

全部改成 `T(key, fallback, params)`，新增 16 个 key，中英双语。

### 2. i18n-msg.js 的 msg() 不替换 $N

带占位符的文案在 ESM 那条通道上会原样显示成 `$1$`。
现在 `msg(key, fallback, params)`，规则和 `t()` 完全一致（`/\$(\d+)\$?/g`）。

### 3. adapters.js 的 getSession() 无 in-flight 去重

一次对比并发 2~4 条，而 token 只该抓一次。加 `sessionPending`，并发共用同一个 Promise。

### 4. 新增「代码 key ⊂ en 包」断言

以前只验中文包。英文缺键会**静默回落中文** —— 切了语言还是中文，很久发现不了。

### 5. 顺带修掉断言自身的一个 bug

新断言启用时立刻抓到：

```js
const enKeys2 = Object.keys(...)   // 数组
k in enKeys2                       // 查的是下标，不是 key！
```

改成 `Set` 之后「代码 key ⊂ en 包 = 是」。

**这条 bug 自己就是「验证器要有夹具」的例证** —— 断言对着错误的东西跑了很久，
一直显示「通过」，因为中文包那侧用的是 `in zhAll`（对象，正确），
英文那侧用的是数组（错误）。

## 五、这一轮的一个教训

我在改 `test-lib.mjs` 时**反复用行号 splice**，把文件结构改坏了十几次，
最后一次不得不 `git checkout` 整体回滚重来。

归根到底是同一个老毛病：**用行号做文本手术**。correct 做法是：

1. 改之前先 `node --check` 记住基线
2. 每次 splice 后立刻检查语法
3. 结构复杂时用**整段函数替换**而不是行号

这条我已经记过好几次了，但还是在犯。
