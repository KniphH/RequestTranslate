## 一、同源检查：三次都选错度量，这次真比对

### 三次失败尝试

| 版本 | 判据 | 为什么不行 |
| --- | --- | --- |
| v1 | 字符串字面量全包含 | 剥注释删掉中文文案、esbuild 改写模板拼接 → 误报 781 段 |
| v2 | 字面量总长 | 剥注释后源码反而更短，方向反了 |
| v3 | 函数计数 | **esbuild 不改它** —— 实测 21 个 .js 的 pf/sf 全是 1.000 |

第九版说得对：三者共同点是**找「不真比对也能判断」的廉价代理**。

而且 `compared += 1` 写了两遍 → 打印「42 个 .js」（实际 21 个）。
我第十四版回应里的「42 个 .js 同源」就是这个 bug 的产物 —— **数字又骗了我一次**。

### 现在做的事

打包流程会产出 `dist/.stripped/` —— 那正是「源码剥注释 + esbuild 压缩」的等价形式，
**也就是包内文件的直接来源**。拿它和包内同名文件比 md5：

```
与源码同源：21/21 个 .js 逐文件 md5 一致
```

两边同源 → 哈希必然相同；包是旧的 → 必然不同。**不需要任何代理指标。**

### 按判据 2 做了夹具，并进了 npm test

新增 `tools/test-pack-fixture.mjs`：拿 `dist/request-translate-1.3.1.zip` 这个**真旧包**跑检查，
断言它必须非零退出。已接入 `npm test`，不再是「手跑一次就算」。

## 二、e2e：环境不全 ≠ 测试失败

以前缺 playwright-core 就 `exit(1)`，而 `pack.py` 打包前跑 npm test ——
**干净机器上 `npm run pack` 必断**，明明代码是对的。

改成两档：

- 默认 **SKIP** + 醒目警告（写明缺什么、怎么装、以及「UI 层 0 覆盖」）
- `RT_REQUIRE_E2E=1` 或 `--require-e2e` 升级为失败（CI 想强制覆盖时用）

SKIP 时写 0 项进汇总，不会被读成「有覆盖」。
