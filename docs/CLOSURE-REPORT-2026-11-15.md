## 1. 验收口径（「闭环」的严格定义）

每条问题必须同时满足 1–4，批次结束再满足 5–6：

1. **代码改动落在具体 `file:line`**，可被独立复核；
2. **至少一条行为断言**（真跑生产函数 / 消息流 / DOM 渲染），或一条可复现命令与预期输出；
   **源码正则不算**；
3. **增量测试通过**（`check-globals` / `check-dom` / `test-lib` / `test-engine` / `test-strip`），
   批次结束跑 `npm test` 全量；
4. **数字与文档按脚本输出同步**，禁止手写「✅ 已修」；条目状态必须给命令或 `file:line`；
5. **打包验证**：`python tools/pack.py --xpi` + `verify-pack` 全过、双包与 `git HEAD` 同源
   （打包期间不动源码）；
6. 台账里标 **已闭环 / 部分 / 影响边界外**，并附验证结论（命令 + 输出摘要）。

**完成标准**：台账无「未闭环 / 部分」项，全量与打包均通过，评价维度达成依据可复核。
单测绿、e2e 绿、局部修好都**不算**完成，不因此停止。
